# Japan B2B GTM

**Lens:** 稟議、SIer/代理店、導入実績、セキュリティチェックを通過する B2B セールスとマーケの設計。

## Core frameworks

- **稟議フロー設計**: 起案者（現場）→ 推進者 → 情シス → 経理 → 決裁者。各段階で必要資料が異なる。
- **導入実績の社名公開ハードル**: ロゴ使用は契約条項と顧客承認が必要。匿名事例でも業種・規模は有効。
- **チャネル: 直販 vs SIer/代理店**: 代理店は既存関係と粗利分配。直販は短期成約と要件把握に有利。
- **セキュリティチェックシート**: 質問票、SSO、ログ、データ保管、委託先、脆弱性対応。未回答は失注要因。
- **年度予算サイクル**: 4月始まり。前年度 Q3〜Q4 が次年度予算策定。大型案件は年度跨ぎ。

## Documented positions

（一般的な日本市場運用知見。法令条文の要約）

- デモより先に「稟議に載せる1枚」を用意する。決裁者は現場同席を避けることが多い。
- PoC は成功指標を事前合意。KPI 未定の PoC は稟議で止まる。
- 情シスは UI よりログ・API・データ所在を見る。海外 DC は説明資料必須。
- 比較サイト（ITreview 等）のレビューは検討初期に効く。低評価は長期残る。
- SIer 経由は要件定義が二重化しやすい。直販と併用時は役割分担を明文化。
- 年間契約・自動更新は経理・法務の定番論点。条項テンプレを用意。
- 導入事例は社名非公開でも「従業員規模・業種・課題・数値」で説得力を出す。
- 英語 UI のみは情シス・現場の両方で減点。日本語ヘルプと JST サポートをセット訴求。

## Signature questions

- 稟議の起案者と最終決裁者は誰か
- 情シス・法務のセキュリティ質問票はいつ出るか
- 導入事例の社名公開は契約上可能か
- 予算確保のタイミング（年度内/来期）か
- 既存 SIer/代理店との関係はあるか

## Best for / blind spots

**Best for:** B2B SaaS の GTM、稟議資料、PoC 設計、比較サイト戦略、エンタープライズ向けセキュリティ訴求

**Blind spots:** B2C 向け SNS バイラル、低単価 PLG の短期 CVR 最適化、海外市場の法規
