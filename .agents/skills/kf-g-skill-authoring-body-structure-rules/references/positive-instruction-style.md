# 肯定形の必須手順

## 基本方針

skill 全体の指示は、エージェントが「何をいつ必ず実行するか」を直接読み取れる形式で書く。
着手条件・手順・出力条件を、番号付きの必須手順として列挙する。

## 必須手順の3要素

| 要素 | 書く内容 | 例 |
| --- | --- | --- |
| 着手条件 | いつこの skill を読み始めるか | 「委譲指示に `skills` 節がある → 列挙 skill を読んでから着手する」 |
| 実行手順 | 読み取り後に必ず踏むステップ | 「1. overview を読む 2. 該当 reference を読む 3. 出力形式に従う」 |
| 出力条件 | 完了時に満たす状態 | 「status / conclusion / evidence を委譲指示の形式で返す」 |

## 書き方の規約

1. 各手順は動詞から始める（「確認する」「読む」「返す」）
1. 条件分岐は「〜のとき → 〜する」の肯定形で書く
1. チェックリストは「〜しているか」で完了判定を明示する
1. 分類語（原則名、観点名）は説明のため使ってよい
1. 本文全体は着手条件・実行手順・出力条件の肯定形リストで構成する

## 変換例

弱い表現を必須手順へ変換する際の対応表。

### 着手条件

| 弱い表現 | 必須手順への変換 |
| --- | --- |
| いきなり実装しない | 設計判断が必要なら、実装前に plan を提示する |
| skill を読まずに進めない | 列挙 skill の SKILL.md を読んでから着手する |

### 実行手順

| 弱い表現 | 必須手順への変換 |
| --- | --- |
| 詳細を SKILL.md に詰め込まない | 詳細は references/ へ分離し、SKILL.md からリンクする |
| 二重判定を避ける | 適用条件は frontmatter description に集約し、本文では手順のみ書く |

### 出力条件

| 弱い表現 | 必須手順への変換 |
| --- | --- |
| 適当に返さない | 委譲指示の report 形式（status / conclusion / evidence）に従って返す |

## 最終チェック

1. 着手条件が「いつ読むか」を明示している
1. 手順が番号付きで実行順を示している
1. 出力条件が完了状態を判定できる
1. 手順が着手条件・実行手順・出力条件の肯定形で構成されている
