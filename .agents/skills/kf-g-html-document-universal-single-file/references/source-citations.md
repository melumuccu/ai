# 出典リンク・外部参照

外部資料を根拠に `[data-content-root]` 本文を書くときの必須手順。

## 適用条件

次のいずれかに該当するとき、本節の手順を適用する。

- 外部ドキュメント、仕様、公式 docs、公開記事などを根拠に、主張・手順・定義を `[data-content-root]` に記載した
- 読者が原文へたどれるようにする必要がある（プランニング、調査、非コーディング文書）

**パターン別必須度**

| パターン | 必須度 |
| --- | --- |
| プランニング、調査、非コーディング（パターン C） | 外部根拠箇所は必須 |
| PR レビュー（パターン A） | 出典を引用した箇所のみ必須 |
| 業務フロー、手動インフラ | 外部根拠箇所があれば必須 |

## リンク化

1. 根拠となる語句または短い主張を、`[data-content-root]` 内の `<a href="確認済みURL">...</a>` にする
1. リンクテキストは根拠の要点（用語、規約名、数値、短い主張）とする
1. リンクの直後に長い括弧 URL を併記しない（`(https://...)` 形式は使わない）

## fragment 優先

1. 該当見出しの `#` 付き URL を優先する
1. fragment の取得手順:
   - 見出しテキストから slug または id を確認する
   - GitHub、MDN など公式の heading anchor を優先する
   - 目次（TOC）や「見出しリンクをコピー」機能から URL を取得する
1. fragment が取れない場合のみページ URL を使う
1. ページ URL のみを使う場合は、取得不能理由を collapse または操作記録に短く残す

## 到達性検証（使用前必須）

リンク化する前に、各 URL の到達性を検証する。

### 手順

1. HEAD で確認する（HEAD 不可なら GET にフォールバックする）
1. 成功: 2xx、または到達可能な 3xx 先
1. 失敗: 404、410、接続失敗、5xx 継続 → **その URL は使用禁止**
1. 失敗時は代替 URL を探す。見つからない場合は未リンクとし、根拠を collapse または操作記録に記載する

### fragment の扱い

- fragment 欠落だけでは到達失敗とみなさない（ページ本体が到達可能なら使用可）
- 可能な範囲で見出し id の存在を確認する

### 認証壁・一時障害

- 認証壁で内容確認不能、または一時障害の場合は代替 URL を探索する
- 代替が見つからない、または検証不能の場合は未リンクとし、根拠を collapse または操作記録に記載する

### 検証手段（例）

| 手段 | 用途 |
| --- | --- |
| `curl -I <URL>` | HEAD でステータス確認（fragment 除く） |
| `curl -L <URL>` | HEAD 失敗時の GET フォールバック |
| `WebFetch` | ページ本文・見出し id の存在確認 |

## 左注釈との関係

| 機能 | 要素 | 用途 |
| --- | --- | --- |
| 左注釈 | `mark[data-term-id]` | 著者定義の専門用語解説 |
| 出典リンク | `<a href="https://...">` | 外部資料への根拠参照 |

混同禁止。専門用語の定義は左注釈、外部資料の引用は本文 `<a>` とする。

## 生成時チェック

1. 外部資料を根拠にした主張がすべて `<a href="...">` でリンク化されているか
1. 可能な箇所で fragment 付き URL を使っているか。ページ URL のみの場合、理由を記録したか
1. 各 URL を到達性検証済みか（404、410、接続失敗、5xx 継続を除外したか）
1. 左注釈（`mark[data-term-id]`）と出典 `<a>` を混同していないか
1. リンクの直後に長い括弧 URL を併記していないか
1. リンク化した出典文言を長文で繰り返していないか（二重記載禁止）

## validator

`node scripts/verify-review-delivery.mjs <html-file> --check-sources` で、`[data-content-root]` 内の外部 http(s) 出典 `<a>` のページ到達性を機械検証できる（opt-in）。詳細は [pr-review-delivery.md](pr-review-delivery.md)。
