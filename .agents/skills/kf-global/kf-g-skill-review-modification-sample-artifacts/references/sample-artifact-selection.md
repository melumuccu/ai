# サンプル成果物種別の選び方

**前提**: 固定プロンプト確定前に本ファイルを読み、成果物種別と同一対象内容を先に固定する。

## 選定原則

1. 対象 skill の主な出力形式に合わせて 1 種別を選ぶ
1. before / after で同じ種別・同じ題材・同じ入力を使う
1. 種別が異なると比較不能になるため、途中変更しない

## 成果物種別の目安

| 対象 skill の主出力 | 推奨成果物種別 | 例 |
| --- | --- | --- |
| HTML 文書・プランニング資料 | 単一 HTML ファイル | コミュ用 HTML、設計資料 |
| Markdown 文書・報告 | Markdown ファイル | 調査報告、手順書 |
| コード生成・整形 | コード断片（言語固定） | 関数、設定スニペット |
| コミットメッセージ・短文 | テキストファイル | 件名 + 本文 |
| 表・比較表 | Markdown または HTML 表 | 比較表 1 枚 |

## 同一対象内容の固定方法

次を 1 セットとして固定し、固定プロンプトに明記する。

1. **題材**: 何について生成するか（例: 「skill 改修の PR 説明文」）
1. **入力データ**: 具体的な素材（例: issue 番号、diff 要約、ユーザー依頼文）
1. **制約**: 文字数、形式、禁止事項（skill 改修で変わる部分以外）
1. **成果物種別**: 上表から 1 つ（拡張子・MIME を含む）

## 選定手順

1. 対象 skill の `description` と references から、主な出力形式を特定する
1. 上表から最も近い種別を 1 つ選ぶ
1. 題材と入力データを具体例で固定する（抽象語だけにしない）
1. [fixed-prompt-template.md](fixed-prompt-template.md) のプレースホルダへ転記する
1. Worker A / B 起動前に、種別・題材・入力が before / after で同一であることを確認する

## 避ける選び方

- before は HTML、after は Markdown のように種別を変えない
- 題材や入力を worker ごとに変えない
- skill 改修の効果が見えないほど入力が単純すぎる題材を選ばない
- 外部 API・秘密情報が必要な題材を選ばない（再現性が落ちる）
