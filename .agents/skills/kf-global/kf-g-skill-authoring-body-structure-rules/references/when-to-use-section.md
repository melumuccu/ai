# 「使う場面」の扱い

## 基本方針

適用条件は frontmatter `description` に集約する。
SKILL.md 本文の「使う場面」は、description の補助情報として、必要な場合だけ置く。

## 通常手順

1. トリガー・適用対象・カバー範囲を frontmatter `description`（1〜2文・英語）へ書く
1. SKILL.md 本文は短い目的のあと、原則概要または参照ファイル一覧へ進む
1. 詳細な境界条件・条件表・長い例は references へ分離する

## 例外条件（「使う場面」を置くとき）

次の条件を**すべて**満たす場合のみ、SKILL.md 本文に「使う場面」を補助的に置く。

1. 適用条件が入り組んでおり、description の推奨長（1〜2文）に主要情報が収まらない
1. description に主要な trigger と適用対象をすでに記載している
1. 本文「使う場面」は詳細補足・境界条件・具体例に限定する

## description と「使う場面」の役割分担

| 場所 | 役割 |
| --- | --- |
| frontmatter `description` | 適用ゲート（エージェントが skill を選ぶ唯一の基準） |
| SKILL.md「使う場面」（例外時のみ） | description の補足（詳細条件・境界・例） |
| references | 条件表・判定フロー・長い例など実行に必要な詳細 |

## 配置と目次化

1. 「使う場面」は適用判定の基準に含めず、判定は description のみとする
1. 詳細な条件表・マトリクスは references へ分離し、SKILL.md からリンクする
1. 「使う場面」節は短い箇条書きに留め、50行行数目安を守る

## 判断フロー

1. 適用条件を description（1〜2文）に書ける → 本文は目的のあと読み進め方へ進む
1. description に主要 trigger を残したうえで補足が必要 → 「使う場面」に詳細・境界・例だけ書く
1. 条件表や長い判定ロジックが必要 → references へ分離し、SKILL.md からリンクする

## 整備手順

1. トリガーと適用対象を description にまとめる
1. description だけで足りるか確認する
1. 足りる場合は本文を目的 → 原則概要/参照一覧 → 読み進め方へ構成する
1. 足りない場合は description の主要情報を維持し、「使う場面」に補足のみ追加する
1. 詳細条件は references へ移し、SKILL.md からリンクする

## 最終チェック

1. 適用判定が description だけで可能である
1. 「使う場面」がある場合、description に主要 trigger と適用対象が残っている
1. 「使う場面」が適用判定の基準に含まれず、詳細補足・境界・例に限定されている
1. 詳細条件表は references へ分離され、SKILL.md から到達できる
