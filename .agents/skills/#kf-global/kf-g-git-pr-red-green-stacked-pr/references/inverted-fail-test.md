# 成否反転テスト（下層 PR）

下層では「通常実行すると失敗するテスト」を CI 上 Green にするため、テストフレームワークの**期待失敗** API を使う。
プロジェクトのランナーに合わせて1つを選ぶ（例のみ。追加調査はプロジェクトの設定を読む）。

| 環境 | API（例） |
| --- | --- |
| Vitest | `test.fails` |
| Jest | `test.failing` |
| Playwright | `test.fail()` |

## テスト名とアサーション

- テスト名は**仕様**の形にする（不具合の症状だけを名前にしない）
- アサーションは正しい期待値を書く（現状の誤動作の値を期待値にしない）
- 上層で反転を外したとき、名前と中身が矛盾しないようにする

## WORKAROUND コメント

`test.fails` 単体では「いつ外すか」がコードから読み取りにくい。下層では次をコメントに残す。

1. なぜ反転しているか（現状実装のどの誤りにより失敗するか）
1. 外す条件（例: 切り捨てに修正したら `.fails` を外す）
1. 検索用の目印（例: `WORKAROUND`）

下層だけが先にマージされた場合でも、後続が判断できるようにする。

## 下層 PR の diff の見え方

- 追加されるのはテストとコメントが中心
- 上層 PR のテスト diff は「反転修飾子と WORKAROUND 削除」に留まり、アサーション変更がないことをレビューで確認する

## 詳細は tdd に委譲

シームの選定、トートロジー回避、垂直スライスなどは [tdd](../../../tdd/SKILL.md) を必ず読む。本ファイルは stacked PR 用の反転表現だけを扱う。
