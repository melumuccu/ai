# 向き不向きと他規約

## 向いているケース

- 挙動の因果をレビューで強く押さえたい不具合修正
- ロジックが複雑で「テストが本当に Red だったか」を毎回手で確認したくない変更
- 回帰テストを追加し、その有効性を CI 履歴に残したいとき

## 向いていないケース

- タイポや影響が閉じた小さな修正（PR が2倍になる手続きコストが勝る）
- 再現テストが安定して書けないもの（フレーク、レース、環境依存の表示崩れなど）
- 反転失敗 API が無く、かつ同等の CI 検証を別手段で用意できないプロジェクト

## [kf-g-git-commit-atomic-rules](../kf-g-git-commit-atomic-rules/SKILL.md) との関係

atomic-rules は「テストが落ちる状態で commit しない」が原則。
本運用の**下層 PR**は、反転 API により CI 上は Green であることを前提にした例外パターンとする。

- ローカルで通常実行すると Red になることは想定内
- マージ前に反転付きで CI Green を確認する
- 下層だけを `main` に残さない（スタックマージで上層とセットで入れる）

## 単一 PR で足りるとき

影響が小さい修正や、再現が自明なときは通常の1 PR + [tdd](../../../tdd/SKILL.md) の Red→Green でよい。
ユーザーが明示的に CI 証跡や stacked 分割を求めたときに本 skill を選ぶ。
