# 作成手順

`概要` / `Why` の定義は [format.md](format.md) を参照する。

## 手順

1. 直近 10 commit の各 1 行目を確認し、既存の type_ や subject に寄せられないか検討する
1. 対象の repo が docs repo かどうかを確認する
1. 変更内容から主目的を 1 つに要約する
1. 8 種類の prefix から最も適切なものを選ぶ
1. 主目的が新機能か、不具合修正かを切り分ける
1. プロジェクトの動作に直接的な影響が無いなら `feat_` を除外する
1. docs repo なら `docs_` を原則除外し、変更の性質に応じて prefix を選び直す
1. 変更対象を短く表すカテゴリを決める
1. 先頭にカテゴリを置き、主目的との間を ` > ` で区切った日本語 subject にする
1. 本文に `概要`（What）と `Why`（判断理由）を書く
1. Why が subject / 概要 / diff の再述になっていないか確認する
1. 長くなる箇所は次の箇条書きへ分ける
1. 体言止め中心で整える
1. 1行目を `<type_>: <カテゴリ> > <subject>` の形にする
1. 2行目を空行にする
1. prefix が 5 文字固定か確認する

## 本文テンプレート

```text
<type_>: <カテゴリ> > <subject (日本語)>

- 概要:
  - 何を変えたか
  - 必要なら次の要点
- Why:
  - なぜこのように実装・変更したか
  - 必要なら根本原因、制約、設計判断、却下した代替案
```

## 書き方の要点

- カテゴリは `skills`、`prompts`、`認証`、`設定画面` のように簡潔にする
- prefix とカテゴリは別に考える
- `feat_` を選ぶ前に、実行時挙動が直接変わるかを確認する
- 一文が長くなりそうなら、次の箇条書きへ分ける
- 1 つの箇条書きには 1 論点だけを書く
- 本文も日本語で簡潔に書く
- 長文より短い箇条書きを優先する
