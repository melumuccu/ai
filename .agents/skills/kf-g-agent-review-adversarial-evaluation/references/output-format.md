# 出力形式

## 必須見出し順

次の見出しをこの順で必ず含める。

1. **結論**（進める / 条件付き / 差し戻し）
1. **Blocking issues**
1. **Non-blocking risks**
1. **Open questions**
1. **受け入れ条件**（条件付きのときのみ）

## 各セクションの書き方

- 各項目は具体的根拠を付ける（引用・仮定の明示）
- 抽象的な「気をつけて」だけで終わらない
- 空セクションは「なし」と書く
- 条件付き承認のときだけ「受け入れ条件」見出しを置く。進める・差し戻しのみのときは省略する

## 指摘項目の書き方

### 実質的分岐があるとき

チャット（Markdown）テンプレ例:

```markdown
- **[指摘]** <内容と根拠>
  - **A**: <対処策> (推奨)
  - **B**: <対処策>
```

### ほぼ1択のとき

偽の第2案を作らず、採用・反映済みを述べる:

```markdown
- **[指摘]** <内容と根拠>
  - 採用して反映済み: <採用した対処策と反映内容>
```

規約:

- 推奨は行末の `(推奨)`（絵文字なし）。推奨が無い場合は付けない
- 実質的分岐があるときだけ A/B 等のラベル付き選択肢を列挙する
- ほぼ1択のときは採用・反映まで完了し、何を採用したかをユーザーに伝える
- HTML（コミュ用）では daisyUI `<span class="badge badge-primary badge-outline">推奨</span>` を用い、`kf-g-html-document-universal-single-file` の badge 規約に従う（チャット規約 `(推奨)` とは分離。形式 skill を上書きしない）

## 出力例（骨格）

### 複数選択肢がある場合

```markdown
## 結論

条件付き — ○○の前提が検証されるまで本番投入は差し控える。

## Blocking issues

- **[指摘]** ○○の前提が未検証
  - **A**: 前提を検証してから再評価 (推奨)
  - **B**: 前提を明示したうえで条件付き承認とする

## Non-blocking risks

- **[指摘]** △△の運用負荷が見積もられていない
  - **A**: 運用コスト見積もりを追加する (推奨)
  - **B**: 現状のまま進め、初回インシデント時に見直す

## Open questions

- ...

## 受け入れ条件

- ...
```

### ほぼ1択の場合

```markdown
## 結論

進める — 指摘は反映済み。

## Non-blocking risks

- **[指摘]** ログ出力に PII が含まれる可能性
  - 採用して反映済み: 該当フィールドをマスクする処理を追加した

## Open questions

- なし
```

進める・差し戻しのみで条件付きでない場合、最後の「受け入れ条件」見出しは出さない。
