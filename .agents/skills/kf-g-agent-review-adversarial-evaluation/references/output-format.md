# 出力形式

## 必須見出し順

次の見出しをこの順で必ず含める。

1. **結論**（進める / 条件付き / 差し戻し）
1. **Blocking issues**
1. **Non-blocking risks**
1. **Open questions**
1. **受け入れ条件**（条件付きのときのみ）

## 各セクションの書き方

- 各項目は具体的根拠を付ける（引用・仮定の明示）
- 抽象的な「気をつけて」だけで終わらない
- 空セクションは「なし」と書く
- 条件付き承認のときだけ「受け入れ条件」見出しを置く。進める・差し戻しのみのときは省略する

## 指摘項目の書き方

チャット（Markdown）テンプレ例:

```markdown
- **[指摘]** <内容と根拠>
  - **A**: <対処策> — `推奨`
  - **B**: <対処策>
```

規約:

- 推奨は行末の `` `推奨` ``（絵文字なし）。推奨が無い場合はバッジを付けない
- 選択肢は A/B 等のラベル付き、原則2件以上
- HTML（コミュ用）では daisyUI `<span class="badge badge-primary badge-outline">推奨</span>` を用い、`kf-g-html-document-universal-single-file` の badge 規約に従う（形式 skill を上書きしない）

## 出力例（骨格）

```markdown
## 結論

条件付き — ○○の前提が検証されるまで本番投入は差し控える。

## Blocking issues

- **[指摘]** ○○の前提が未検証
  - **A**: 前提を検証してから再評価 — `推奨`
  - **B**: 前提を明示したうえで条件付き承認とする

## Non-blocking risks

- **[指摘]** △△の運用負荷が見積もられていない
  - **A**: 運用コスト見積もりを追加する — `推奨`
  - **B**: 現状のまま進め、初回インシデント時に見直す

## Open questions

- ...

## 受け入れ条件

- ...
```

進める・差し戻しのみで条件付きでない場合、最後の「受け入れ条件」見出しは出さない。
