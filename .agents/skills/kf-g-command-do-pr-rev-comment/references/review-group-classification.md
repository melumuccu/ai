# 論理グループ分類

## 目的

未解決 review comment を、atomic commit 可能な論理変更グループへ分類する。

## 分類手順

1. 未解決 thread をすべて列挙する
1. 各 thread の指摘内容・対象ファイル・修正種別（コード / ドキュメント / 運用手順）を整理する
1. 次の観点でグループ候補を作る
   - 同じ修正理由で説明できるか
   - 同じレビュー観点（命名統一、運用追加、不要削除など）に属するか
   - 別 commit に分けた方が diff が読みやすいか
1. グループ候補を統合または分割し、最終グループ一覧を確定する
1. 各グループに対応 thread を割り当てる

## グループ化の判断基準

| 状況 | 扱い |
| --- | --- |
| 同じ用語・形式を複数ファイルで統一する | 1 グループ（横断統一） |
| 同じ機能領域の仕様変更（例: description 統合規則） | 1 グループ |
| 独立した運用手順の追加（例: Wrangler OAuth） | 別グループ |
| 参照資料から不要節を削除 | 別グループ（削除理由が独立） |
| 同じファイル内の無関係な修正 | 別グループ |
| 1 thread が複数の独立修正を含む | thread を論理単位へ分解して複数グループへ割り当てる |

## 分類時の禁止

- 未分類のまま実装を始めない
- 「全部まとめて 1 commit」で進めない
- 1 コメント = 1 commit とは限らない（論理変更単位で分類した結果、1 コメント = 1 commit になる場合もある）

## 分類結果の記録形式

作業前に次の形式で残す。

```markdown
## 論理グループ一覧

### G1: {識別名}
- 変更理由: {1 行}
- 対象 thread: {URL または ID 一覧}
- 主な対象ファイル: {path 一覧}

### G2: {識別名}
...
```

## 分類例

7 件の review comment がある場合、次の 4 グループが自然な例。

| グループ | 内容 | 含まれる指摘例 |
| --- | --- | --- |
| G1 | `v{N}` とカスタム URL の横断統一 | 表記統一、公開先 URL 固定 |
| G2 | Issue description の統合・上書き規則 | 追記禁止、統合方針 |
| G3 | Wrangler OAuth 運用の追加 | 認証手順 |
| G4 | R2 参照資料の不要節削除 | 公式参照、localStorage 一般論、CORS 記述 |

G1 は複数 thread を 1 グループにまとめる例。
G3 と G4 は独立した修正理由のため別グループにする例。
